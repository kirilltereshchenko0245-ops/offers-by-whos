# Система клиентских ботов

## Как это работает

Один главный бот (OfferBot) управляет множеством клиентских ботов пользователей. Все боты работают на одном сервере и используют одну базу данных.

### Архитектура

```
┌─────────────────────────────────────────┐
│         Главный бот (OfferBot)          │
│   - Продажа доступа                     │
│   - Управление клиентскими ботами       │
│   - Админка                             │
└─────────────────────────────────────────┘
                    │
                    ├── Bot Manager
                    │
        ┌───────────┼───────────┬───────────┐
        │           │           │           │
    ┌───▼───┐   ┌───▼───┐   ┌───▼───┐   ┌───▼───┐
    │Bot #1 │   │Bot #2 │   │Bot #3 │   │Bot #N │
    │User A │   │User B │   │User C │   │User X │
    └───────┘   └───────┘   └───────┘   └───────┘
```

## Для пользователей

### Как добавить своего бота

1. **Купить доступ** в главном боте
2. **Создать бота** через @BotFather
3. **Добавить токен:**
   ```
   /mybots - показать ваших ботов
   /addbot - добавить нового бота
   ```
4. **Подключить Telegram Business** к вашему боту
5. **Отправлять оферы** через вашего бота:
   ```
   купить https://t.me/nft/... 150 грам
   ```

### Команды пользователя

- `/mybots` — список ваших ботов
- `/addbot` — добавить нового бота
- Кнопка "🗑 Удалить бота" — удалить бота

### Лимиты

- **Максимум 5 ботов** на одного пользователя
- Все боты работают только пока у вас есть активный доступ
- Если доступ истёк — все ваши боты перестают работать

## Для администратора

### Команды админа

```bash
/admin          # Админка с информацией о боте
/botlist        # Список всех клиентских ботов

# Управление конкретным ботом
/startbot 123   # Запустить бота с ID 123
/stopbot 123    # Остановить бота с ID 123
/deletebot 123  # Удалить бота с ID 123
```

### База данных

Новая таблица `client_bots`:

```sql
CREATE TABLE client_bots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    owner_id INTEGER NOT NULL,           -- Telegram ID владельца
    token TEXT NOT NULL UNIQUE,          -- Токен бота
    username TEXT,                       -- Username бота (@botname)
    is_active INTEGER DEFAULT 1,         -- Активен ли бот
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    last_error TEXT                      -- Последняя ошибка
);
```

### Логирование

Все действия логируются с префиксом `[BOT {id}]`:

```
[BOT 5] Started for user 123456789
[BOT 5] Business connection id=xxx user_id=123456789
[BOT 5] Stopped
```

## Технические детали

### BotManager

Класс `BotManager` управляет всеми клиентскими ботами:

- `load_all_bots()` — загрузка всех активных ботов при старте
- `start_bot(bot_id, token, owner_id)` — запуск одного бота
- `stop_bot(bot_id)` — остановка бота
- `restart_bot(bot_id)` — перезапуск бота
- `stop_all()` — остановка всех ботов (при выключении сервера)

### ClientBot

Каждый клиентский бот — это экземпляр класса `ClientBot`:

- Собственный `Bot` и `Dispatcher`
- Обработчики для Business сообщений
- Проверка доступа владельца перед каждым офером
- Изолированная работа (боты не влияют друг на друга)

### Безопасность

1. **Проверка токена** при добавлении через `bot.get_me()`
2. **Проверка доступа** владельца при каждом офере
3. **Изоляция ботов** — падение одного не влияет на другие
4. **Уникальность токенов** — один токен = один бот

### Автозапуск

При запуске главного бота:

1. Загружаются все активные боты из БД
2. Каждый бот проверяется и запускается
3. Если бот не запускается — логируется ошибка, остальные продолжают работу

### Остановка

При остановке главного бота:

1. Вызывается `bot_manager.stop_all()`
2. Все клиентские боты корректно останавливаются
3. Все сессии закрываются

## Преимущества системы

1. **Один сервер** — все боты на одной машине
2. **Одна база данных** — легко управлять и мониторить
3. **Простота для пользователей** — просто отправь токен
4. **Контроль доступа** — боты работают только с активным доступом
5. **Масштабируемость** — легко добавлять новых ботов
6. **Изоляция** — проблема с одним ботом не влияет на другие

## Мониторинг

Для мониторинга доступны:

- Логи с префиксами `[BOT {id}]`
- Таблица `client_bots` с last_error
- Команда `/botlist` для админа
- Статусы ботов (🟢 Запущен / 🔴 Остановлен)
